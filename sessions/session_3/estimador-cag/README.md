# CAG Software Estimator

Session 3 exercise of the LIDR AI Engineering master. It starts from the Session 2 estimator (FastAPI project scaffolding) and adds a streaming chat on top of it.

The service receives the transcript of a client meeting and returns a software estimate
generated by an LLM (OpenAI `gpt-4o-mini`).

**Architecture: CAG (Cache-Augmented Generation).** Three past estimates travel as static
context inside every prompt. There is no database, no retrieval and no persistence:
the examples are small enough to fit in the model's context window.

```
POST /api/v1/estimate  {"transcription": "..."}
  -> [system] instructions + 3 past estimates  (app/context/examples.py)
  -> [user]   the transcript
  -> LLM answer (Markdown estimate)  ->  JSON response
```

## Structure

```

├── app/
│   ├── main.py              # FastAPI app: router under /api/v1, GET /health, Swagger docs
│   ├── config.py            # settings from .env (Pydantic BaseSettings, fails fast without a key)
│   ├── routers/
│   │   └── estimations.py   # POST /estimate: request/response schemas, LLM errors -> 502
│   ├── services/
│   │   └── llm_service.py   # system prompt + examples, OpenAI Responses API call
│   └── context/
│       └── examples.py      # the static CAG context: 3 past estimates at 60 USD/hour
├── scripts/
│   └── validate.py          # validation pipeline (structure, security, running service)
├── transcripts/
│   └── landing_page_hubspot.json   # the meeting transcript used for this exercise
├── .env.example             # variables the project needs (no values)
├── .gitignore               # keeps .env and .venv out of Git
└── pyproject.toml
```

## Setup

Requirements: Python 3.11, [uv](https://docs.astral.sh/uv/), an OpenAI API key with credit.

```bash
uv sync                    # install the dependencies in .venv
cp .env.example .env       # then put your key after OPENAI_API_KEY= in .env
```

`.env` is in `.gitignore`. Never commit it.

## Run

Terminal 1 (from this folder):

```bash
uv run uvicorn app.main:app --reload
```

Terminal 2:

```bash
curl http://localhost:8000/health

curl -X POST http://localhost:8000/api/v1/estimate \
  -H "Content-Type: application/json" \
  -d @transcripts/landing_page_hubspot.json
```

Swagger UI: <http://localhost:8000/docs>

On Windows PowerShell, write `curl.exe` instead of `curl` (`curl` there is another command).

## Validation

```bash
uv run python scripts/validate.py          # free checks, no LLM call
uv run python scripts/validate.py --live   # also one real estimate (< 0.01 USD)
```

It prints `[PASS]`/`[FAIL]` per check and ends with `RESULT: OK` or `RESULT: FAIL`
(exit code 0 or 1). It checks:

1. **Structure**: every file of the brief exists; the required dependencies are declared.
2. **Configuration and security**: `.env.example` documents the variables, `.env` is git-ignored,
   no API key appears in the code, the settings load, the math of each context example is correct.
3. **Running service**: the server starts, `GET /health` → 200, `/docs` → 200,
   empty transcript → 422. With `--live`: a real estimate whose task hours add up to the total
   and whose cost = total × rate.

## The exercise transcript

[`transcripts/landing_page_hubspot.json`](transcripts/landing_page_hubspot.json) (the brief's
test transcript, translated to English):

> In the meeting with the marketing team, the client explained that they need a landing page with
> a contact form, integration with their current CRM (HubSpot), and a blog section with a WYSIWYG
> editor. The ideal deadline would be to have it ready in 4 weeks. The design already exists in Figma.

Result on 2026-11-20 (`gpt-4o-mini-2024-07-18`, 1,106 input / 213 output tokens):

| Task | Hours |
|---|---|
| Frontend development (landing page and blog section) | 40 |
| Integration with CRM (HubSpot API for lead creation) | 20 |
| WYSIWYG editor setup for the blog | 24 |
| Contact form with validation and spam protection | 8 |
| Testing and QA | 12 |
| Deployment and handover | 4 |
| **Total** | **108 h = 6,480 USD** |

Duration 4-5 weeks; team: 1 full-stack developer + 1 QA tester (part-time).

What worked: the math is correct; it used the closest example (corporate website + CRM) and
removed the design hours because the design already exists in Figma.

Notes for the live session (quality is not expected to be perfect yet):

1. It copies example 2 almost exactly: all six task hours are the same.
2. The duration contradicts itself: "4-5 weeks", but "the 4-week deadline is feasible";
   108 hours is less than 3 weeks for one full-time developer.
3. It adds a role ("QA tester") that no example uses.
